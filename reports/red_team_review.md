# Red-Team Review — acquisition-conditioned SAR detector

Status: **pre-results review.** The repository contains a built, tested pipeline
(`saryolo/`, 328 tests) and **no measured cross-sensor numbers yet** — the real
datasets (SSDD, HRSID, SARDet-100K) are not present in the working environment.
This review therefore attacks the *design and the protocol*. Any verdict that
requires a measurement is marked `BLOCKED-ON-RUN` and must be re-answered before
these conclusions are quoted anywhere.

Reviewer stance: hostile. Goal is to find the weaknesses first.

---

## W1 — Is the adapter novel, or another FiLM plug-in?

**Severity: HIGH.**

Conditional feature modulation is old and well-published (FiLM, conditional
batch-norm, domain-adversarial branches, sensor-token conditioning). SARFormer
(CVPR 2025) already encodes acquisition parameters for SAR representation
learning. "Metadata-conditioned adapter" alone is not a contribution.

- What defends it today: the contribution is framed as *failure analysis +
  protocol + diagnosis* (LOSO folds, sensor-vs-class separability probes,
  field-withholding study), with the adapter as the minimal mechanism the
  diagnosis motivates. `docs/research_gap.md` records the crowded-module
  literature this deliberately avoids.
- `BLOCKED-ON-RUN`: the probe results must actually show sensor-dominance in
  baseline features that conditioning reduces. If they do not, the mechanism
  loses its motivation and the paper has no story.

## W2 — Metadata circularity at test time

**Severity: HIGH.**

If the adapter needs a correct sensor ID at inference, then on an *unseen*
sensor it cannot have one — the method must work when the only honest label is
"unknown". The smoke test pins that a held-out source encodes to the reserved
unknown row (`tests/test_conditioning_smoke.py`), and the field-mask module
makes a withheld field indistinguishable from a never-recorded one
(`tests/test_field_mask.py`).

- `BLOCKED-ON-RUN`: the degradation curve (all fields → none) must be measured.
  If accuracy collapses without metadata, the deployment claim dies and must be
  reported as a limitation, not hidden.

## W3 — Geography masquerading as sensor shift

**Severity: HIGH.**

SSDD/HRSID scenes are not independent; a leave-one-source-out split can still
leave the same harbour or coastline in train and test. A "cross-sensor gap"
could partly be a scene gap.

- What defends it today: the leakage audit and split tooling exist
  (`saryolo/data/groups.py`, validation reports under `results/resolved_data/`).
- `BLOCKED-ON-RUN`: the audit must be executed on the real images (perceptual
  hashing, scene overlap), and the sensor-confusion matrix must be compared
  against a scene-blocked split. If the gap shrinks under scene blocking, the
  sensor claim must be re-scoped.

## W4 — Is the comparison parameter-matched?

**Severity: MEDIUM.**

Any adapter adds parameters; a gain from +0.3 M params is not a mechanism.

- What defends it today: the variant zoo includes a parameter-reduced arm
  (`v2_full_p35_s`) generated by `scripts/make_exp_configs.py` precisely so a
  capacity-matched control can be run; the efficiency table reports params and
  FLOPs from the same ledger rows.
- `BLOCKED-ON-RUN`: the in-domain and LOSO tables must include the
  capacity-matched control, or reviewers will attribute the gain to capacity.

## W5 — Statistical power

**Severity: MEDIUM.**

Three seeds (EXP-012 arms `seed0/1/2`) give a noisy std. An improvement smaller
than the seed spread is not evidence.

- What defends it today: `build_multi_seed` reports mean ± sample std **and
  best/worst**, counts one row per training seed (a restarted run cannot
  double-count), and renders TBD for anything unmeasured — the table cannot be
  filled by hand.
- `BLOCKED-ON-RUN`: if the effect size is within one std, the honest claim is
  "no detectable difference at this budget", not a win.

## W6 — One architecture is not a principle

**Severity: MEDIUM.**

Everything currently runs on the YOLO11-family graph. The master workflow
requires demonstrating the mechanism on a second detector (RT-DETR) before
calling it architecture-general.

*Update (feasibility arm built):* `SARYOLORTDetectionModel`
(`saryolo/nn/model.py`) plus the generator-derived variant
(`configs/models/rtdetr/rtdetr_s_cond_film.yaml`, produced by
`scripts/make_rtdetr_variant.py`) prove the conditioned adapter inserts into an
RT-DETR graph, that vocabulary preparation works through the *same*
`prepare_conditioned_config` path as YOLO, that a held-out sensor lands on the
unknown row, and that the graph stays bit-identical to stock at init
(`tests/test_rtdetr_arm.py`). **This is feasibility, not a measured result** —
the RT-DETR training-loop integration (task-map wiring, loss checks) remains
open, and no cross-architecture claim may be made until a LOSO number exists.

## W7 — Protocol fairness

**Severity: LOW (already engineered against).**

- Splits and folds are generated once and written to config (`loso` writer
  propagates `metadata_fields` so no fold runs under a different protocol).
- Tables are ledger-derived only; a missing cell is `TBD`, never a number.
- The probe conditions a conditioned checkpoint on its own acquisition, so the
  baseline-vs-conditioned representation comparison is not silently run with
  "unknown" metadata.

## W8 — Cross-resolution claims on HRSID

**Severity: MEDIUM.**

The HRSID release states three resolutions but ships no per-chip mapping, so a
per-image resolution axis would be *fabricated* unless sourced externally. The
docs and config reflect this honestly (fields stay null; the runbook routes
resolution experiments through a sourced sidecar). Any cross-resolution table
built before that sidecar exists would be invalid.

## Strengths a reviewer cannot remove

1. **No fabricated numbers by construction** — the ledger records only measured
   values and the table builder refuses to fill gaps.
2. **The failure protocol is the contribution** — LOSO folds, metadata
   withholding, and representation probes are pinned by end-to-end tests, so
   the diagnosis is reproducible independently of the detector's accuracy.
3. **Negative results are representable** — failed runs persist in the ledger,
   and incomplete tables ship with an explicit warning rather than being
   withheld.

---

## Verdict

The design survives a hostile reading *as a protocol contribution with a
hypothesised mechanism*. It does **not** yet survive as an empirical paper:
every quantitative claim is `BLOCKED-ON-RUN`, the RT-DETR transfer (W6) is
unimplemented, and the dataset-side work (W3 audit, W8 sidecar) needs files
that are not on disk. Ordered next actions:

1. Put SSDD on disk and run the LOSO baseline + conditioned arms (the
   runbooks are ready).
2. Run the field-withholding curve (W2) and the capacity-matched control (W4).
3. Implement the RT-DETR arm (W6) before any architecture-generality claim.
4. Re-answer W1/W3/W5 from measurements and rewrite this document from
   "blocked" to "answered".
