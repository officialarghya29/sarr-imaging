# Paper workflow

```
paper/
├── manuscript/
│   ├── main.tex      complete section skeleton (CVPR style)
│   └── refs.bib      bibliography
├── tables/           GENERATED by `python -m saryolo assets`
└── figures/          GENERATED by saryolo.paper.figures
```

## Generating assets

```bash
python -m saryolo assets                       # tables -> paper/tables (TBD for unmeasured cells)
python -m saryolo assets --require-complete    # fails if any cell is unmeasured
```

`--require-complete` is the submission gate: it converts "some experiments are
still missing" from something a tired author might not notice into a hard error.

## The no-fabrication rule

Every cell in every table comes from `results/experiments.jsonl` or from a JSON
artefact that an evaluation run actually wrote. A value that was never measured
renders as `TBD`, and there is no code path that fills a cell with a plausible
number, a zero, or an interpolation. If a table is incomplete, the honest actions
are to run the experiment or to say in the text that it was not run.

Two further rules are encoded in the generators:

* **An unmeasurable metric is `None`, never `0.0`.** If a dataset has no large
  objects, `AP_large` is not measurable; reporting `0.0` would read as the model
  failing on large objects. `saryolo.paper.figures.plot_scale_ap` marks such bars
  `n/a` instead of drawing a zero-height bar.
* **Failed runs are retained.** The ledger is append-only and keeps failed rows
  with their error, so a table can never silently include a run that did not
  finish.

## Claim-checking discipline

The paper's argument is only as strong as the controls, so they are named
explicitly:

| Claim | Supported only if | Control experiment |
| --- | --- | --- |
| Local-contrast enhancement helps | `EXP-002` beats `EXP-001` | `pre_identity`, `pre_log`, `pre_clahe`, `pre_standardize` |
| Speckle-aware suppression helps | `EXP-003` beats `EXP-002` | `spk_none`, `spk_lee`, `spk_denoise` |
| **The attention is *adaptive*** | `att_saa_static` underperforms `EXP-004` | `att_saa_static` |
| Attention beats standard blocks | `EXP-004` beats `att_se`/`att_eca`/`att_cbam` | same-slot baselines |
| **The fusion is *adaptive*** | `fus_static` underperforms `EXP-005` | `fus_static` |
| The P2 head is justified | dataset size distribution is small-dominated | `EXP-006` vs `EXP-005`, `AP_small` |
| The SAR loss helps | `EXP-007` beats `EXP-008` | `EXP-008` (architecture identical, loss off) |
| Results are stable | multi-seed std is small | `EXP-012` |

If `att_saa_static` matches `att_saa`, the word "adaptive" must be removed from
the contribution list — the block still works, but not for the stated reason.
The same applies to `fus_static`. Stating this in advance is deliberate: it is
much easier to decide honestly before seeing the numbers.

## Figures

`FIGURE_PLAN` in `saryolo.paper.figures` maps each planned figure to the data it
requires, so a figure cannot be drawn before its experiment exists:

| Figure | Content | Data source |
| --- | --- | --- |
| 1 | Motivation: speckle, clutter, low contrast, small targets | `dataset_statistics/` |
| 2–6 | Architecture and each module | drawn manually (TikZ / diagram tool) |
| 7 | Qualitative: GT vs baseline vs SAR-YOLO | `saryolo.visualization.detections` |
| 8 | Grad-CAM / feature maps | `saryolo.visualization.attention_maps` |
| 9 | Robustness curves | `results/robustness/robustness.json` |
| 10 | mAP vs FPS / params / FLOPs | ledger |
| 11 | Failure taxonomy | `saryolo.visualization.error_analysis` |

Architecture diagrams (Figures 2–6) are intentionally *not* auto-generated:
a generated block diagram is rarely publication quality. The module docstrings in
`docs/METHOD.md` contain the exact equations and data flow those diagrams should
depict.

## Writing order that works

1. Fill Table 1 (dataset statistics) — it constrains which components are
   justifiable at all, notably the P2 head.
2. Run and fill Tables 2–4 (baseline, main ablation, module ablation). These
   decide the story.
3. Only then write the abstract and introduction, so they describe results that
   exist rather than results that were hoped for.
4. Robustness, efficiency, generalisation and multi-seed last.
5. Add the limitations paragraph from what the controls actually showed.

## Before submission

```bash
python -m saryolo assets --require-complete   # no TBD cells anywhere
pytest tests/ -q                              # architecture invariants still hold
python -m saryolo ledger                      # every table row traceable to a run id
```

Also verify `refs.bib` entries against the publisher records — several venue and
page fields are intentionally left blank rather than guessed.
